# Website redirects

Nginx serves the generated website and handles HTTP redirects using two maps.
Changes to these files require rebuilding and deploying the website container.

## Temporary redirects (302)

Add manual temporary redirects to [temporary-redirects.conf](temporary-redirects.conf).
Each entry contains a source path or regex pattern and a complete destination URL,
followed by a semicolon:

```nginx
~^/enterprise-support/?$ https://platform.cloudogu.com/en/support/offer/;
```

The map matches `$uri`, so query strings do not affect matching and are not
automatically forwarded to the destination. For example, both
`/enterprise-support` and `/enterprise-support/?source=website` redirect directly
to `https://platform.cloudogu.com/en/support/offer/`.

The shared handler in [nginx.conf](nginx.conf) always returns 302 and runs before
trailing-slash normalization and the permanent redirect handler. Unmatched paths
continue through normal request handling.

## Generated permanent redirects (301)

[redirects.conf](redirects.conf) contains legacy permanent redirects. It is
generated by [scripts/create-redirect-map.js](../../scripts/create-redirect-map.js)
from hardcoded legacy routes and blog post slugs. The generated file is tracked
in Git. Regeneration is manual; from the repository root, run:

```sh
node scripts/create-redirect-map.js
```

The generator overwrites the entire file. Make changes in the generator or its
source content rather than editing `redirects.conf` directly.

The permanent map uses `$request_uri`, which includes the query string. Its
destinations are local paths; Nginx prepends the website's HTTPS hostname and
returns 301. This behavior is separate from the temporary redirect map.
